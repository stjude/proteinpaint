Features:
- Scatter hover now runs the shared cover/quadtree pipeline (client/dom/dataPointInteractions) that manhattan, GRIN2 and the volcano plots already use. The cursor picks the nearest dot rather than whichever one happens to be painted on top, hover rings mark exactly which dots the tooltip is reporting, and a click opens the standard action menu (Sample view / Disco / Met Array / Lollipop) instead of buttons injected into the tooltip body. The nested coordinate/color/shape/scale tooltip tree is replaced by the module's flat table, so a multi-dot hover lists one row per sample rather than counts per category; single-dot content is unchanged. settings.sampleScatter.maxTooltipRows (default 5) caps that table
- DataPointInteractionsOpts gains an optional toLocalCoords hook for plots whose points live inside a zoomed or panned <g>. Scatter passes pointer(event, serie.node()), which inverts the full screen CTM and lands in the untransformed space the quadtree was built in, so the tree is built once and never rebuilt on zoom or pan. Existing callers are unaffected
- DataPointInteractions gains destroy(), which detaches and then disposes of its click Menu. detach() alone leaves the Menu's div and its body-level listener behind, which matters for any caller that builds a new instance per render rather than reusing one

Fixes:
- Scatter: a geneVariant color term in groupset mode discarded the colors assigned in its edit menu. Those categories are keyed by group name, which matches nothing in term.values, so termdb.sampleScatter fell through to an ordinal scale and both the dots and the legend showed arbitrary colors — the predefined groupsets lost their meaning too (#e75480 mutated, mclass WT wildtype). The route now resolves the active groupset with get_active_groupset(), the same helper that produced those group names upstream in mds3.init. A recolor from the plot legend still wins over the groupset color. snp and categorical groupsets broke identically through the same line and are fixed with it. The lookup is wrapped, since get_active_groupset() validates and throws on a malformed groupset and nothing calls it upstream on the queries.snvindel.byisoform path — a color-only defect must not fail the whole scatter request
- Scatter: the hover neighbourhood reported dots that were nowhere near the cursor. Distances were measured after clamping both points into a box derived from xAxisScale.invert(0)..invert(svgw), but the axis range starts at the 80px axis gutter, so every sample in the rightmost 80px collapsed onto one x and the bottom 30px onto one y. The threshold was also a fixed 5/zoom with no relation to the rendered dot size: zoomed out it reached about 12 dot radii, zoomed in it caught only exactly coincident dots. A dot is now a neighbour when its rendered circle overlaps the hovered one, using the actual radius (8 * getScale), which is zoom-invariant and already accounts for scaleDotTW sizing, refSize and the search-match enlargement
- Scatter: a dot hidden by a legend click no longer opens a tooltip. SVG hit-testing ignores fill-opacity, so hovering an invisible dot used to report its visible neighbours
- Scatter: the cursor's forgiveness margin around a dot is a constant 3 screen px, and the hover ring a constant 2 screen px, at every zoom level. Both were previously measured in the plot's own coordinate space, so zooming in inflated them along with the dots — at 10x that is 30px of grab area around every dot and a ring that reads as a halo rather than an outline
- Scatter: the lasso's sample table pads the Info cell on rows that have no info. The header was appended once for the whole table while the cell was only pushed for rows that had the field, so any row without it came out one cell short and its values shifted left under the wrong headers. That table also formats its values now (geneVariant mname, dates, numeric rounding), matching the hover table, since both are built from one shared function
- dom/Menu: show2() flips the menu above the anchor point when it does not fit below, which show() already did. Without it a menu opened near the bottom of the window ran off-screen with no way to scroll to it on a page that does not itself scroll. This affects every show2() caller — the manhattan/GRIN2, volcano and cohort-volcano hover tooltips as well as scatter
- dom/Menu: destroy() removes the uniquely-namespaced mousedown listener the constructor registers on <body>. It previously removed only the menu's div, so every discarded Menu left a listener behind that outlived it

DevOps:
- Scatter hover precomputes each dot's projected center and rendered radius once per attach, rather than recomputing them through the d3 scales on every mousemove. The broad-query radius scanned every sample per event and the cluster step scanned them again per hit, which put an O(n) sweep over up to 20000 samples on plain cursor movement
- scatterTooltip.unit.spec is rebuilt around the real axis geometry, with the range offset by xAxisOffSet. Its predecessor exercised the now-deleted distance() through a mock whose range started at 0, which is exactly what hid the edge-clamping bug above; the new cases pin the neighbourhood radius, the per-dot scaleDotTW radius, and the constant screen-pixel cursor margin and hover ring across four zoom levels. Both margins are asserted against their constants rather than literals, so the property under test is that they do not change with zoom. scatter.integration now asserts groupset fill colors instead of category labels alone
